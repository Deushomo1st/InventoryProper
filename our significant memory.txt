## Hard rules (do not violate)

1. Every downstream service has its own `JwtAuthFilter` wired into `SecurityConfig` via `addFilterBefore`. Services do not trust the gateway — they trust the JWT signature.
2. JWT secret is shared via `INVENTORY_JWT_SECRET` env var. Never hardcode.
3. **Dual-access mode is mandatory.** Each service runs through the gateway (`:9000/ui/{service}/...`) AND directly on its own port. Each service has its OWN copy of `static/login.html`, `static/js/app.js`, `static/css/style.css` — keep them byte-identical with the gateway's. These are intentional duplicates, not dead code.
4. `sessionStorage` keys: `inv_jwt`, `inv_user`. User object: `{ id, email }`.
5. Plain HTML/CSS/JS only. No framework. No build step. No npm.
6. UTF-8 forced in `application.properties` of every service.
7. Permissions live in JWT claims (computed at login). Permission/role changes require re-login.
8. 401 = "I don't know who you are" → client bounces to login. 403 = "I know you, not allowed" → show error. Never collapse them.
9. Theme tokens are in `:root` of `style.css`. Use them — never hardcode colors. Accent is `#00ff88` (green glow), surface `#111118`, border `#2a2a3a`.

## Mistakes prior AIs made

- Deleted the auth-service's duplicate `static/js/app.js` and `static/css/style.css` thinking they were dead code → broke direct-access mode.
- Wrote pages using `.container`, `.service-content`, `.service-toolbar` CSS classes that don't exist → page renders as unstyled browser defaults next to themed pages.
- Built modals with `style="display:none"` toggled by `style.display = 'block'` → wrong pattern; we use `.modal-back` wrapper + `.classList.add('show')` for backdrop blur and animation.
- Added a `Permissions` tab linking to a page that didn't exist → 404 on click.
- Stripped `/ui/{service}` prefix in `RouteController` before forwarding → broke static file serving on downstream services.
